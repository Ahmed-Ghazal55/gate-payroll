# كشف المندوب المبسط — API 0.8.0

مسار قراءة فقط، داخل نفس جلسة وصلاحية `debts.view` المستخدمة للكشف الحالي:

```http
GET /api/finance/statement/rider/2000000999/simple?from=2026-10&to=2026-10&sponsorId=BW
```

كل بيانات المثال اصطناعية. `from` و`to` مطلوبان بصيغة `YYYY-MM`، شاملان لشهري البداية والنهاية، والبداية لا تتجاوز النهاية. `sponsorId` اختياري: رمز الشركة أو معرفها المعتمد؛ حذفه أو تركه فارغًا يجمع **الشركات المسموح بها فقط**. تاريخ الاستحقاق هو `journal.period`؛ تاريخ إنشاء القيد لا ينقل الحركة لشهر آخر. الرصيد الافتتاحي يجمع القيود السابقة لـ`from`، والإقفال يشمل القيود حتى `to` فقط.

## المصدر والصلاحيات

- المسار يستخدم `store.Read` فقط؛ لا حفظ ولا Audit جديد ولا تغيير مخطط أو Migration. لا يقرأ مصدرًا بديلًا لملء صافي الرصيد.
- المصدر المالي: كل سطر داخل وثيقة `journal` مثبتة يحمل `iqama` المطلوب، حتى لو رأس القيد يحمل إقامة أخرى أو كان فارغًا. الوثائق القديمة دون `status` قيود مثبتة؛ `status` الصريح يجب أن يكون `posted`؛ المسودات لا تدخل الكشف.
- الشركة من **سطر القيد وقت الحدث**، وليست الكفيل الحالي أو دائن الدين الحالي. اختيار شركة خارج النطاق يرجع 403. فئة الدين ومنصته تُفحصان مثل الكشف الحالي، مع تجاوز Admin/SuperAdmin. الرواتب تتطلب أيضًا `payroll.view`.
- للسطر الذي لا يرتبط بدين، تُستخدم فئة/منصة السطر أو الرأس عند وجودهما، أو منصة جاهز الصريحة في نوع/حساب الحركة. لمسير الراتب تُستخدم منصات `run.sourceRows` المحفوظة. إذا كان السطر مختلط المنصات أو بلا دليل يسمح بعزله، يلزم السماح بكل منصاته، أو بكل المنصات عند غياب الدليل. الدين المفقود لا يمنح صلاحية لفئته/منصته؛ يُحجب عن غير المسؤول. لا يُفترض أن شركة أو منصة المستخدم هي صاحبة البيانات المجهولة.
- لا توجد حركة مرئية تُحذف بسبب نوع غير معروف، أو لأنها طرف مقابل للشركة. الحجب للصلاحيات يسبق حساب الأرصدة والتجميع، ويشمل الفترات السابقة أيضًا. إذا لم يكن للمستخدم حق في ملف المندوب أو أي تاريخ مالي ظاهر له، يرجع 403 دون كشف بيانات الرأس.

## معاني الحقول والإشارات

| الحقل | المعنى |
|---|---|
| `rider` | رأس مختصر: الإقامة والاسم والمدينة والحالة؛ لا هاتف ولا بيانات بنكية |
| `openingBalance` | صافي القيود المرئية قبل أول شهر مطلوب، دون ديون تاريخية غير مثبتة |
| `months` | صف لكل شهر في النطاق، بما فيه الشهر الخالي: افتتاحه، مجاميع البنود، الحركة، والإقفال |
| `details` | كل سطر مرئي في الفترة، بترتيب الشهر ثم التاريخ ثم مرجع القيد ورقم السطر؛ لا دمج يخفي السطر المقابل |
| `labelAr` / `description` | تسمية عربية بسيطة، ووصف المصدر للتتبع. النوع المجهول يحافظ على وصفه بدل إسقاطه |
| `amount` | مبلغ السطر بإشارته: الموجب يزيد حق المندوب أو يخفض دينه في سطور رصيده، والسالب عكس ذلك. للسطر المقابل يُعرض مبلغ الحركة فقط ولا يُجمع كحق أو خصم جديد |
| `affectsNet` / `netAmount` | هل السطر يغير صافي المندوب، ومقدار التغيير؛ السطر المقابل للشركة `false` و0. لا تجمع `amount` لكل التفاصيل للوصول للصافي |
| `salaryAmount` | حصة السطر في رصيد المستحقات وعجز الرواتب؛ صفر في غيرها |
| `jahezCashAmount` | حصة السطر في دين كاش جاهز المرحّل المثبت على المندوب؛ منفصلة عن الراتب |
| `journalId` + `lineNumber` | رابط التدقيق إلى القيد الأصلي وموقع السطر بترتيب مصفوفته؛ ليست صلاحية لعرض قيد أو شركة أخرى |
| `periodTotals` / `months[].totals` | مجاميع **`netAmount`** لكل بند، بإشاراتها؛ تظل كل البنود موجودة ولو صفرًا. لا تضيف الأطراف المقابلة إيرادًا/خصمًا ثانيًا |
| `netMovement` | مجموع أثر الفترة: الكسب موجب، والخصم/الصرف/زيادة الدين سالب؛ التحصيل أو الإعفاء موجب لأنه يقلل الدين، وليس راتبًا جديدًا |
| `closingNet` | الافتتاح + الحركة. موجب: الشركة مدينة للمندوب؛ سالب: المندوب مدين للشركة؛ صفر: لا رصيد |
| `closingSalaryNet` | المستحقات المعتمدة بعد الصرف والاستقطاع وعجز الرواتب، دون دين كاش جاهز المرحّل أو بقية ذمم الخدمات |
| `openingJahezCashNet` / `closingJahezCashNet` | كاش جاهز المثبت على المندوب؛ السالب ما زال مطلوبًا تسليمه، والموجب تسوية لصالحه. لا يُجمع التزام الشركة لجاهز مرة ثانية |
| `closingOtherDebtNet` | باقي ذمم المندوب المثبتة؛ بحيث `closingSalaryNet + closingJahezCashNet + closingOtherDebtNet = closingNet` |
| `transactionTypes` | كل نوع ظهر في تفاصيل الفترة والبنود التي صُنفت فيها سطوره؛ التصنيف للسطر وليس للرأس فقط لأن مسيرًا واحدًا قد يحتوي كسبًا وخصمًا |

مطابقة الرصيد، لكل نطاق وفترة: الرصيد الطبيعي لمستحقات 2110 **ناقص** الرصيد الطبيعي لذمم 1210 و1211 و1230. جميعها تُحسب من الأسطر المثبتة الحاملة للإقامة. لا تدخل حسابات أموال الشركة أو المصروفات أو الجاري في الصافي مرة ثانية. لا تُعاد صناعة رصيد من سجل `ledger` أو `debt.remainingBalance`.

## تصنيف كل أنواع القيود الموجودة في كود الترحيل

كل سطر له **بند واحد فقط**. النوع يحدد طبيعة الحدث، والحساب واتجاه المبلغ يحددان موضع أثره على المندوب. لهذا لا يصح اعتبار رأس `payroll_accrual` كله كسبًا. الأطراف المقابلة محفوظة عادة في `other` بأثر صفر؛ الأسطر الجارية في `transferred` بأثر صفر. الأنواع المستقبلية دائمًا `other` مع الوصف، ولو حملت رصيدًا للمندوب يظل أثرها في الصافي.

| `transactionType` | بند سطر المندوب وقاعدته |
|---|---|
| `payroll_accrual` | `earned` لزيادة 2110 من الأجر المعتمد؛ `deducted` لخصومات المسير/المركبة/الغرامات منه. 1211: `debt_added` أو `debt_collected` بالإشارة |
| `payroll_deduction` | `deducted` من 2110؛ تخفيض 1210/1230 في `debt_collected` أو `jahez_cash`؛ القسط يخفض المستحق والدين معًا، فلا يخفض الصافي الكلي مرتين |
| `payroll_payment` | `received` لخروج مستحق من 2110؛ الصرف سالب في الصافي. الطرف البنكي مقابل بأثر صفر |
| `intercompany_debt_transfer` | `transferred` لكل سطر؛ نقل الذمة يغير رصيد كل شركة بقدر أسطر ذمة المندوب، ومجموع الشركات لا يكرر الدين |
| `opening_balance_debt` | `debt_added`/`debt_collected` حسب الإشارة؛ ذمة كاش جاهز: `jahez_cash` |
| `debt_accrual` | نفس قاعدة الذمة؛ كامل المصروف الذي تتحمله الشركة لا يزيد دين المندوب |
| `debt_creation` | نفس قاعدة الذمة؛ لا يعامل صرف السلفة كراتب إضافي |
| `debt_recognition` | نفس قاعدة الذمة للاستيراد التاريخي المثبت |
| `legacy_debt_opening` | نفس قاعدة الذمة؛ افتتاح **راجعَه واعتمدَه** المسار الموجود، وليس إنشاء افتتاح عند القراءة |
| `reviewed_opening` | ذمة 1210/1211/1230 حسب الإشارة؛ تسوية 2110 في `other`، تؤثر بالصافي ولا تُسمى راتبًا مكتسبًا جديدًا |
| `cash_collection` | `debt_collected` لتخفيض الذمة، أو `jahez_cash` عند تسليم كاش جاهز؛ النقدية مقابل لا يُجمع ثانية |
| `bulk_collection` | نفس قاعدة التحصيل |
| `collection_with_waiver` | `debt_collected` لتخفيض الدين بسداد/إعفاء، أو `jahez_cash` للذمة الخاصة بجاهز؛ لا يوصف كله كاش مستلم من المندوب |
| `administrative_waiver` | `debt_collected` كتخفيض معتمد، أو `jahez_cash` للذمة الخاصة بجاهز؛ التسمية توضح أنه إعفاء وليس قبضًا |
| `company_expense` | `other` في تكلفة الشركة والطرف المقابل، بأثر صفر على المندوب؛ إن حملت ذمة مثبتة فتصنف حسب الذمة |
| `supplier_payment` | `other`؛ دفع التزام مورد يخص الشركة، لا صرف راتب للمندوب. الجاري `transferred` |
| `legacy_cash_allocation` | `other` لتوزيع نقدية الشركة؛ لا تغير صافي المندوب بمجرد وجود إقامة |
| `vault_transfer` | `other` لحركة نقدية الشركة، والجاري `transferred`؛ لا دخل جديد للمندوب |
| `jahez_account_fee` | `other` لرسوم الشركة؛ لا يُخلط صندوق الرسوم بعهدة كاش الطلبات |
| `company_fee_deposit` | `other`؛ إيداع حصيلة الشركة لا يكرر كسب المندوب |
| `jahez_custody_transfer` | `jahez_cash` لحركة العهدة؛ أثرها على صافي المندوب صفر ما لم تحمل ذمته المثبتة |
| `jahez_platform_settlement` | `jahez_cash` لتسوية الشركة مع جاهز؛ ليست راتبًا للمندوب |
| `jahez_eod_handover` | `jahez_cash` للعهدة، دون خصم راتب أو تحصيل ذمة ثانية |
| أي نوع غير معروف أو فارغ | `other` مع وصف المصدر، محفوظ في التفاصيل ومؤثر بالصافي إذا كان من حسابات رصيد المندوب |

زوجا فصل عجز الراتب ومقاصته في `payroll_accrual` يحملان البند نفسه على طرفيهما (`debt_added`/`debt_collected`)؛ أثر الزوج صفري، فلا تظهر إعادة التصنيف كسبًا جديدًا أو خصمًا إضافيًا. دين كاش جاهز هو 1230 مع منصة Jahez من سياق مثبت؛ أما 2140 وصناديق العهدة فهي أطراف/أموال تخص الشركة وتظهر منفصلة دون إضافتها مرة ثانية. إذا كان المصدر القديم يضع عجزًا في 1211 فسيظل عجز رواتب بحسب حسابه؛ لا تُجرى إعادة تصنيف تخمينية عند القراءة.

## الديون القديمة غير المطابقة

تبقى `legacyEvidenceIncomplete: true` و`historyCoverage: legacy_requires_review` عند وجود دين قديم بلا افتتاح مربوط. تظهر الذمم المرئية في `legacyUnverifiedDebts` بمرجعها وشركتها والرصيد التاريخي والتحذير؛ وفي التفاصيل يبقى العلم على السطر المرتبط بها أيضًا. المثال:

```json
{
  "debtId": "legacy-example",
  "sponsorId": "company-example",
  "remainingBalance": 75.00,
  "legacyEvidenceIncomplete": true,
  "labelAr": "دين قديم يحتاج مطابقة؛ غير مضاف إلى صافي القيود المثبتة"
}
```

هذه قائمة تحذير عن السجل التاريخي الحالي، بشركة الدائن الحالية الخاضعة للنطاق، وليست حركة داخل الفترة المطلوبة. لا تنسب قيمة السجل الحالي لشركته القديمة عند انتقاله؛ الأسطر المثبتة وحدها تتبع ملكية الشركة التاريخية وقت الحدث. لا تُضاف قيمها إلى الافتتاح أو الأشهر أو الإقفال، ولا تُحفظ تسوية أو قيد لإجبار المطابقة؛ فقط الأسطر المثبتة تدخل الصافي.

أخطاء الطلب: 400 للتاريخ/الإقامة/الشركة غير الصالحة أو النطاق المعكوس، 401 للجلسة الغائبة، 403 للصلاحية أو نطاق الشركة/المندوب، و405 لمحاولة الكتابة على هذا المسار. لا توجد حقول مدين/دائن في الاستجابة.
