# تحديث 0.6.0 — المالية وملفات المناديب مع حفظ بيانات الإنتاج

- سجل الديون الموسع، التحصيل والإعفاءات والتحويل بين السجلات والقيود المتوازنة، وملف المندوب ومستنداته الخاصة.
- استيراد الأرصدة والتحصيل مرتبط بمعاينة موقعة لمدة 20 دقيقة، للمستخدم نفسه ومع حالة البيانات الحالية. التغيير أو التكرار يوقف الحفظ، والدفعة ذرية.
- بوابة المندوب تتطلب رمز دخول تصدره الإدارة بعد مراجعة الهوية وآخر أربعة أرقام من الجوال. رابط الدخول يملأ الرمز تلقائيًا، والجلسة صالحة 8 ساعات؛ لا كشف مالي بالإقامة وحدها.
- صلاحيات المراجع تبقى لمراجعة النماذج والدليل المختصر؛ لا صلاحية للدفاتر أو ملفات الهوية أو القرارات المالية. إعدادات الربط والاعتمادات المالية للمسؤول.
- عند الترقية تُحفظ نسخة خاصة متسقة من قاعدة البيانات ومفاتيح الجلسات والإعداد المحلي داخل `App_Data/release-backups/0.6.0/`. يتم التحقق من تطابق وثائق التخزين قبل إضافة الفهارس وبعدها، دون إعادة كتابة السجلات القديمة.
- الإشعارات الجديدة تظهر داخل بوابة المندوب. إعدادات Firebase محفوظة تمهيدًا للربط؛ الإرسال الخارجي FCM والنشر في Google Play غير منفذين بهذا الإصدار.
- لا تستبدل قاعدة السيرفر بقاعدة جهاز التطوير، ولا تنشر مجلدات البيانات والأسرار في GitHub. النشر يرفع الكود والأصول فقط، ويحافظ على بيانات الإنتاج وروابط الحملات ومفاتيح الجلسات.

## تحديث 0.5.5 — تحسينات الواجهة والتنقل والجدول

- **روابط عميقة للتابات (Hash Routes):** دعم التنقل المباشر عبر الرابط (مثل `#/responses` و `#/forms`) ومشاركة روابط الشاشات مع الحفاظ على حالة التبويب عند إعادة التحميل وتسجيل الدخول.
- **أعمدة ديناميكية لجدول الردود:** عمودا المدينة والجوال يظهران تلقائيًا فقط عندما تتضمن بيانات الردود قيمًا لها، لمنع الحقول الفارغة غير المفعلة في النموذج.
- **عرض الرد المختار في دليل المناديب:** إضافة عمود «الرد المختار» في جدول دليل المناديب لربط اختيار المندوب المسجل بحالته الحالية.
- **عرض متكامل للجدول دون تمرير أفقي:** ضبط عرض الأعمدة والحشوات لتناسب الشاشات المكتبية واللابتوب القياسية (1280px+) دون حاجة للتمرير الأفقي.
- **أيقونة الفلتر والإغلاق بالنقر الخارجي:** استبدال سهم الفلتر بأيقونة SVG قمع تصفية واضحة، مع إغلاق قائمة التصفية ونوافذ الحوار بمجرد النقر خارجها أو الضغط على Escape.
- **مؤشرات تحميل وحالة الأزرار:** إضافة دوران تحميل وتنسيق مهدئ على أزرار الحفظ والاعتماد الفوري والجماعي لتجنب تكرار الضغط.
- **شارة الردود المعلقة في القائمة الجانبية:** عرض عدد الردود المنتظرة للمراجعة كشارة مباشرة في شريط التنقل الجانبي.
- تحديث الأعمدة بعد حذف الردود يحافظ على تطابق العناوين والخلايا والفلاتر والتصدير، مع تجاهل روابط التنقل غير الصالحة بأمان.
- **تثبيت عناوين الجداول (Sticky Headers):** تثبيت صفوف العناوين وحقول التصفية أعلى الجدول أثناء التمرير العمودي.

## تحديث 0.5.4 — حذف النموذج

زر «حذف النموذج» بجانب التعديل في شاشة النماذج، ومتاح كذلك في مصمم النماذج للمسودات والمنشور. المسؤول فقط يستطيع الحذف. نافذة التأكيد تبيّن عدد الردود المرتبطة وتطلب تأكيد الحذف النهائي للنموذج وردوده؛ يتوقف رابط المشاركة بعدها. إذا تغير النموذج أو الردود بعد فتح النافذة، تُعاد المعاينة ويُلزم تأكيد جديد. الحذف مع التدقيق في معاملة واحدة ويحافظ على دليل المناديب والدفاتر المالية؛ تفضيل الاختيار المرتبط يُسوّى بالطريقة نفسها عند حذف الردود.

## تحديث 0.5.3

تتيح شاشة الردود حذفًا نهائيًا للمسؤول، واعتماد الردود الظاهرة دفعة واحدة للمسؤول والمراجع. اختر حملة قبل الحذف الجماعي؛ كل إجراء جماعي يطبق على الصفوف الظاهرة ويحتاج تأكيدًا. الحذف يحرر الإقامة للتسجيل الجديد ويزيل نسخ الرد، مع إبقاء حدث التدقيق والدفاتر المالية ودليل المندوب. يُزال تفضيل الاختيار المرتبط بالرد المحذوف أو يُستعاد آخر اختيار معتمد باقٍ، دون تغيير سياسة الحساب. الآيبان القديم يحتاج مراجعة فردية ولا يُعتمد جماعيًا.

من «تعديل النموذج» يمكن تغيير العنوان والانتهاء والحالة وتفعيل المدينة والجوال، مع الاحتفاظ بالرابط. الحقول الإضافية مطلوبة عند تفعيلها، وتظهر بثلاث لغات وتُحفظ في تاريخ النسخ. قالب الاختيارات v3 يضيف المدينة والجوال؛ قالب الثلاثة أعمدة السابق يعمل للحملات دون حقول إضافية. الاستيراد يظل معاينة ثم حفظًا ذريًا.

«تحليل النماذج» يجمع الحملات والنماذج المخصصة في قائمة واحدة، مع مؤشرات ورسوم SVG وتوزيع المدن والعلاقة حسب دليل المندوب وأحدث خمسة ردود. الحقول المجهولة تُعرض صراحة ولا تُفترض كفالة أو مدينة. البناء والنشر الآلي يحافظان على App_Data وappsettings.Local.json.

# Gate Payroll — الإصدار 0.5.5

تطبيق ASP.NET Core 10 وTypeScript لإدارة المناديب والرواتب والديون والنماذج. الإدارة والفورم والاستعلام تعمل على أصل HTTPS واحد. مصدر الإدارة Frontend/src، ومصدر الواجهة العامة RiderForm/src، والخادم Payroll.Api؛ البناء مستقل عن المجلد05.

الأدوار Admin وAccountant وReviewer مفروضة على الخادم. الفورم يبدأ بثلاثة حقول أساسية مع إمكانية تفعيل المدينة والجوال، واختياره لا يعيّن سياسة راتب. يضيف الإصدار نماذج مخصصة بثلاث لغات وتحليلات، وروابط محفوظة وQR، ودليلًا موسعًا متوافقًا مع مفاهيم Employee وSponsor، وديونًا بأقساط لا تُرحل إلا عند اعتماد المسير. وصف العمولة يتبع البوستر الحالي وفق تأكيد المستخدم؛ لا أجر ثابت لكل طلب ولا حساب رانك من عدد الطلبات بالتخمين.

تحديث 0.5.2 يعرض الاختيار السابق عند إدخال إقامة مسجلة ويتيح تعديله مباشرة دون رموز أو لصق إيصال، وفق قرار المستخدم. هذا مسار عام لمن يملك رابط الحملة والإقامة، وليس تحققًا من هوية صاحبها؛ لا يعرض سوى بيانات الاختيار، ويبقى كل تعديل بانتظار مراجعة الإدارة مع حفظ تاريخ النسخ. شاشة النجاح تتيح تنزيل إشعار نصي بثلاث لغات من بيانات الرد وتوقيته الفعلي على الخادم. النشر إلى MonsterASP يتم آليًا عبر FTPS بعد نجاح اختبارات دفع main، مع حفظ App_Data وappsettings.Local.json. راجع [عقد الردود](API_CONTRACT.md#response-revisions-052) و[دليل النشر](DEPLOYMENT_AR.md).

## التشغيل والتحقق

يتطلب .NET 10 SDK وNode.js 24. من جذر المستودع:

```bash
npm ci --prefix RiderForm
python3 scripts/fetch_fonts.py
./run-local.sh
```

على Windows استخدم Run-Local.ps1. العنوان المحلي http://127.0.0.1:5188. حساب المسؤول الموجود يظل صالحًا؛ لا توجد كلمة مرور افتراضية. ملفات الخطوط الثلاثة ورخص OFL تُجلب من revision ثابت مع تحقق بصمات، ثم تُخدم من الموقع نفسه دون CDN في المتصفح. يمكن بناء TypeScript محليًا دون الخطوط باستعمال خطوط النظام البديلة.

```bash
dotnet build Payroll.Api/Payroll.Api.csproj --warnaserror
dotnet test tests/Engine.Tests/Engine.Tests.csproj
node tests/integration.mjs
node tests/enterprise.mjs
node tests/submissions.mjs
node tests/campaigns.mjs
node tests/production.mjs
python3 scripts/release_source.py --check
```

MSTest يشغّل الفحوص القديمة الـ52 واختبارات الإصدار الجديد، ويطلق اختبارات HTTP الأصلية والمؤسسية والإنتاج عبر Node.js من داخل dotnet test أيضًا. SQL Server integration يحتاج PAYROLL_TEST_SQL_CONNECTION لقاعدة اختبار معزولة؛ يوفره GitHub Actions بحاوية مؤقتة. الاختبارات تستخدم قواعد مؤقتة، ولا تستخدم قاعدة الإنتاج أو بيانات الأشخاص الحقيقية. `tests/browser-v05.mjs` يتطلب Playwright؛ workflow يثبّت الإصدار المحدد ويجري فحص اللغات والمظاهر والفلاتر والتصدير والجوال.

## النشر والبيانات

GitHub للكود فقط؛ data وApp_Data وprivate-data والمفاتيح والنسخ الاحتياطية مستبعدة. الحزمة Windows x64 ذاتية الاحتواء تُنشأ بعد اجتياز CI وتُنزل باسم publish.zip. حافظ على App_Data ومفاتيحه وappsettings.Local.json عند التحديث. دليل التنفيذ في DEPLOYMENT_AR.md، والعقود في API_CONTRACT.md، وفروق الترقية وحدودها في UPGRADE_V05_AR.md.

SQLite WAL هو الافتراضي. وجود ConnectionStrings:DefaultConnection يختار SQL Server صراحة؛ فشل الإعداد أو الاتصال لا يفتح قاعدة SQLite بديلة بصمت. توجد أداة نقل مستندات خاصة في tools/StoreMigration، وليست هناك كتابة إلى قاعدة ERP أو ترحيل إنتاج منفذ آليًا.

الاستعلام المالي يتطلب الإقامة وآخر4أرقام من الجوال المسجل ورمزًا عشوائيًا لمرة واحدة صالحًا10دقائق صادرًا بعد مراجعة الهوية. لا تُستخدم آخر4أرقام وحدها كمصادقة، ولا توجد خدمة SMS موصولة تلقائيًا. دليل الديون وكشف الراتب المعتمد فقط هما ما يظهر لصاحب التحقق؛ بيانات الإدارة والمصادر الخام لا تُنشر.
